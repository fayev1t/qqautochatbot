# 工具：`send_messages`

## 功能

`send_messages` 向当前群发送一条或多条有序气泡（单次 1–10 个有序气泡）。
一条气泡就够时发一条，不必为了凑数拆句。`messages` 是唯一业务参数，目标群由
当前 `scope_key` 注入，不存在 `target` 或 `group_id` 参数。

写下这个调用的那一拍，一个气泡都不会发出去：整段源码先作为一条决策事件停在
时间线上。要真的发出去，得在后面某一拍重新读完时间线之后写
`execute_program(program_hash=…)` 指名它。所以措辞属于写下它的那一刻，而"还该不该
这么说"属于按下执行键的那一刻——中间到达的消息你都看得见。

## 参数

```python
send_messages(messages=[
    {"text": "周日会提前关门，最好五点前到"},
    {"meme": "a1b2c3d4e5f6"},
])
```

`messages` 为非空数组，一条或多条均可，最多 10 项，按数组顺序发送。**一项就是
一条消息**，两种气泡平级、可任意穿插。

### 文字气泡

日常发言默认只发纯文本：

```python
{"text": "好呀，晚点一起去"}
```

只有 `text` 是常规负载。其余三个键仅在特定需要时作为修饰补充，**普通发言默认不要填**：

- `reply`：可选消歧修饰，**普通发言默认不填**。仅在群聊多话题并行、场面混乱或隔了较久、不指名就会产生严重指代歧义时，才取时间线 `#消息ID` 记号里的号原样照抄（引用只作用于本条气泡）。正常连续对话或接话顺着说即可，不要每句都带引用。
- `at`：可选。要 @ 的 QQ 号，可给单个或数组；`"all"` 表示 @全体成员。@ 出现在本条文字之前。
- `face`：可选。QQ 系统表情 ID，可给单个或数组，出现在本条文字之后。发表情包用 meme 气泡，不是这个。

```python
# 仅在多人同时聊多个不同话题、必须明确指着某条历史消息说话时才带 reply：
{"text": "这篇写得挺清楚的", "reply": "8871"}
```

只 @ 某人或只发一个系统表情时可以省略 `text`；四个键全空的气泡会导致整次调用在
发送前失败。一条气泡内 @ 一律在文字前、系统表情一律在文字后——要别的排布就拆成
两条气泡。

### 表情包气泡

```python
{"meme": "<memes> 区块中 <meme> 行的 12 位 hash 前缀>"}
```

`meme` 必须指向当前表情包收藏中的一张（12 位前缀即可，也接受完整 64 位）。该
气泡只发这张图，不能同时带文字——想配文字就另起一条文字气泡。meme 数量不单独
设限，只受 `messages` 总数上限约束。发送前会统一检查收藏记录与媒体文件；任一项
无效时不会发送任何气泡。

组稿时可扫一遍表情包收藏节。表情包不要求与当前话题精确对应；大致情绪、
弱关联、画面本身有趣或单纯穿插均可，允许形成轻微无厘头的效果。meme 气泡可
以单独代替文字，也可与文字气泡按数组顺序自由穿插，无须增加文字解释二者
为何相关。`meme` 从 `<meme>` 行的 12 位前缀原样照抄即可；照抄无误的
hash 不会在发送前校验上失败。

## 执行与记录

同一次调用中的气泡按顺序逐项发送。每次 `send_messages` 调用都是独立发送
命令；运行时不会合并或去重两次调用。该调用自身
`<tool>send_messages` 行块中的逐气泡内容与逐气泡回执构成发送记录，不会另外生成
第二处发言行（`<legacy_reply>` 仅属旧链路历史）。

## 返回状态

返回值包含 `status` 和逐气泡 `receipts`：

- `sent`：全部气泡拿到 OneBot 成功响应与 `message_id`，工具终态为成功；这只
  表示下游协议已确认，不证明用户端最终可见。
- `partial`：部分气泡拿到成功响应、其余被 OneBot 明确拒绝，工具终态为失败。
  回执中 `status="sent"` 的气泡不得因其余项失败而重发。
- `failed`：全部气泡明确未送达，工具终态为失败。
- `uncertain`：至少一个气泡的送达状态无法确认，工具终态为失败。该状态表示
  对应气泡可能已经送达；再次调用会产生新的独立发送命令，可能形成重复消息。

`invalid_arguments` 会通过 `reason_code` 标识具体参数问题。

## 失败之后不要在同一段程序里补发

调用失败不中止程序，因此形如 `if not r.ok: send_messages(...)` 在语法上是写得
出来的——**但对本函数不要这么写**。`partial` 表示一部分气泡已经发出去了，
`uncertain` 表示那条可能已经发出去了，两种情况下补发都会在群里形成重复消息，
而运行时不判重、不去重。失败之后正确的做法是让这一拍结束，由下一拍对着时间线
上的逐气泡回执重新判断到底说没说出去。
